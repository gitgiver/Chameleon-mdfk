# 2.6 复杂度与正确性分析

本节从正确性、复杂度与判定行为三个方面分析叶型判定机制。正确性部分证明该机制不改变索引的语义；复杂度部分给出点查、范围查询与构建过程的开销上界；判定行为部分则通过式 (2-9) 的变形说明权重如何影响判定结果，从而表明该机制的行为是可解释、可预期的。

## 2.6.1 正确性

叶型判定的引入不应改变索引对外的查询语义：无论某个叶子最终是有序叶还是哈希叶，它都必须存放该叶子应负责的全部键，并对其上的点查与范围查询给出与前缀相同的答案。下面按不变式的形式给出这一性质的保证。

**不变式一：叶内键集合不变。** 叶子所负责的键集合在其被判定之前已经由自顶向下的区间划分确定。判定过程只读取该集合，并在两种叶型中选择一种来存放它：构造候选哈希叶时，集合中的每个键都被插入恰好一次；构造有序叶时，键集合被按键升序写入前 n 个槽。两种构造方式都不会增加、删除或迁移键到其他叶子。因此判定前后每个叶子承载的键集合完全相同，索引对键空间的分区不因判定而改变。

**不变式二：哈希叶的位图与探测范围一致。** 哈希叶的位图标记槽是否已写入有效键值对。点查在比较键之前先检查位图，因此未写入的槽永远不会被误判为命中；同时，插入过程维护最大探测半径 r：若新键在既有半径内找不到空槽，插入会继续向外探测并将 r 更新为该次探测的距离。由此可得，任一已存储的键到其起始桶的距离都不超过当前的 r，而 r 只增不减。点查的探测范围覆盖 i = 0, 1, …, r，因而必然经过该键所在的槽。所以哈希叶的点查既不会漏掉已存在的键，也不会返回不存在的键。

**不变式三：有序叶的键序不变。** 有序叶的前 n 个槽按键升序连续存放。点查先以叶内最小键与最大键建立线性模型并定位预测位置 p，再通过 gallop 把搜索范围收缩到包含目标键的括号区间，最后在该区间内二分。gallop 与二分都只在有序序列上有定义，而键序由构造过程保证，因此这一过程或者返回键的真实位置，或者正确判定其不存在。需要说明的边界情形是目标键落在叶的最小键与最大键之外：此时线性模型直接判定其不属于该叶，无需进入搜索，结论同样正确。

**范围查询的完备性。** 有序叶先对 lo 做二分得到首个不小于 lo 的位置，再顺序扫描到首个大于 hi 的键为止，恰好且仅收集区间内的键，输出自然有序。哈希叶的槽不按键序排列，因此其范围查询遍历全部 c 个槽，逐槽检查位图与键区间；虽然输出顺序与有序叶不同，但收集到的键集合相同，二者在多重集意义下等价。这一等价性正是 2.2.3 节将结果输出代价视为两叶型相同、并在式 (2-7) 中略去的依据。

**确定性。** 判定只依赖叶子自身的键集合、容量、装载因子与权重，不引入随机数，也不依赖叶子的处理顺序。因此相同输入必然产生相同的叶型选择；当两侧代价相等时，式 (2-8) 的严格小于规则统一选择哈希叶，消除了比较结果的歧义。

## 2.6.2 复杂度

**点查。** 哈希叶的点查代价由最大探测半径决定，最坏为 O(r)，单次访问槽数不超过 2r + 1；在均匀散列假设下，装载因子为 α 时其期望代价为 O(1/(1−α))。有序叶的点查代价为一次预测访问加上 gallop 与二分，设预测偏差窗口为 g，则为 1 + O(log g) + O(log g)；由于 g ≤ n，最坏为 O(log n)。两种叶型的点查都只在单个叶子内完成，跨叶的路由代价由树高决定，不因叶型选择而改变。

**范围查询。** 设结果规模为 m。有序叶的代价为定位的 O(log n) 加上输出 m 个键的 O(m)，即 O(log n + m)；哈希叶必须扫描全部 c 个槽并输出 m 个键，代价为 O(c + m)。由于 c ≥ n，哈希叶的范围代价随叶子规模线性增长，这正是 2.2.3 节强调的差异。

**构建。** 对单个叶子，构造候选哈希叶并插入全部键的期望代价为 O(n)，测量 μ_H 需要再做 n 次点查，每次不超过 2r + 1 个槽，故该部分期望为 O(n·r̄)，其中 r̄ 为平均探测半径；模拟有序叶查找最坏为 O(n log n)。由于各叶子顺序处理，整个构建的额外时间不超过 O(Σ n_l log n_l) ≤ O(N log n_max)，与 2.5.3 节的结论一致。额外空间的峰值为一个候选哈希叶，即 O(n_max)，且判定完成后若选择有序叶则立即释放，不进入最终索引。

**索引空间。** 判定确定后，索引的常驻空间等于各叶子选中结构的容量之和。有序叶每键占 1 个槽，哈希叶每键占 1/α 个槽，故判定结果直接决定了空间放大的比例，这也正是式 (2-9) 中内存项的含义。

## 2.6.3 判定行为分析

将式 (2-9) 移项，可以得到有序叶被选中的等价条件：

w_q · (μ_O − μ_H) < w_r · (c − log₂ n) + w_m · (c/n − 1)        (2-10)

式 (2-10) 左端是有序叶在点查上的潜在损失，右端是它在范围定位与内存上获得的收益之和。判定选择有序叶，当且仅当收益严格大于损失。由此可以直接得到该判定的几条性质。

**性质一：权重只具有相对意义。** 若将 w_q、w_r、w_m 同时乘以任意正数 λ，式 (2-10) 两端同比例放大，不等号方向不变。这与 2.3.2 节的说明一致：判定只取决于三者的比例，而不取决于其绝对取值。

**性质二：对权重单调。** 增大 w_m 或 w_r 会增大式 (2-10) 的右端，使结果更倾向于有序叶；增大 w_q 会增大左端，使结果更倾向于哈希叶。因此，当负载更看重内存或范围查询时，机制会自动提高有序叶的比例，而不需要重新设定任何阈值。

**性质三：极端权重下退化为单一目标。** 当 w_q = 0、w_r = 0、w_m > 0 时，判定只最小化内存，由于 m_O = 1 ≤ m_H = c/n，所有满足 n > N_min 的叶子都选择有序叶；当 w_q > 0、w_r = w_m = 0 时，判定只比较点查代价，等价于选择 μ 较小的一侧；当 w_r > 0、其余权重为 0 时，由于 ρ_O = log₂ n 严格小于 ρ_H = c（n > 1），所有满足条件的叶子同样选择有序叶。这三种退化情形分别对应纯内存优化、纯点查优化与纯范围优化，说明式 (2-9) 的加权形式没有引入额外的假设，而是把三个单项目标统一在一个框架内。

**性质四：预测精度通过点查项影响判定。** 点查项中只有 μ_O 随叶内数据分布变化：局部越接近均匀，预测偏差窗口 g 越小，μ_O 越接近 1，式 (2-10) 的左端越小，有序叶越容易被选中；局部偏斜越强，g 越大，μ_O 随 log g 增长，有序叶的代价上升。因此，式 (2-9) 虽然不显式以偏斜度或预测误差为判据，却通过 μ_O 的实测值间接反映了这两者的影响，这也是它能够替代基于阈值的启发式判定的原因。

综合本节的分析，叶型判定在不改变索引语义的前提下，把额外开销控制在叶子尺度；其判定结果是权重与叶子自身特征的确定性函数，且随权重和预测精度的变化表现出单调、可解释的行为。至此第二章的设计与分析部分已经完整，2.7 节对本章内容进行总结。
