# 2.5 与索引构建流程的集成

2.4 节的判定以单个叶子为对象，本节说明它如何嵌入索引的整体构建流程，以及这一嵌入对原有流程的影响。集成的核心原则是“先分区、后定型”：树形与叶子边界由原有的数据划分过程决定，叶型判定只在划分结束后、对已经确定键集合的叶子执行一次，不反过来影响分区结果。

## 2.5.1 判定在构建流程中的位置

索引采用自顶向下的批量构建方式，其流程可分为三个阶段。

第一阶段是输入准备。批量构建要求数据集按键升序排列，这一要求由调用方保证；有序叶的稠密布局正是利用了这一性质，因此判定过程中不需要对叶子内的键重新排序，仅在检测到输入未严格有序时才做一次排序兜底。

第二阶段是自顶向下的区间划分。根节点覆盖整个键空间，策略网络以当前区间的数据特征与偏斜度为输入，决定该内部节点的扇出；随后按等宽键区间把当前区间划分为若干子区间，并对其中的非叶区间继续上述过程，直到某个区间的划分结果为“不再分裂”。此时该区间内键的集合与边界已经完全确定，成为最终索引中的一个叶子。

第三阶段是叶子定型，也是叶型判定唯一介入的位置。对第二阶段产生的每个叶子，以其键集合 K、规模 n 与键区间 [lower, upper] 为输入，执行算法 2-1：先在目标装载因子下构造候选哈希叶并测量 μ_H，再按有序叶路径模拟得到 μ_O，最后由式 (2-9) 在两种叶型之间取小，并直接返回被选中的结构。判定结束后，叶子被挂接到其父内部节点的对应槽位，内部节点组装完成后整棵树构建结束。

这一位置安排带来两个性质。其一，判定是局部的：它只看到本叶子的键与容量，不感知兄弟叶子、父节点或整棵树的状态，因此式 (2-5) 的逐叶分解在实现层面严格成立。其二，判定是终态的：叶子边界在判定之前已经由划分过程确定，叶型选择不会触发重新划分，也不会改变树高或路由路径，从而避免判定与树形决策之间出现相互依赖的循环。

## 2.5.2 判定与树形决策的分工

在整体设计中，树形决策与叶型决策解决的是两个不同层次的问题，二者互不替代。

树形决策由 TSMDP 与多智能体机制完成，它在构建阶段自顶向下进行，决定“数据在什么位置被切开、每层有多少个孩子”，其结果体现为索引的层级与扇出。该决策需要感知全局的偏斜分布，因为扇出的影响会沿路径累积。

叶型决策则由本章的双侧代价模型完成，它在树形确定之后逐叶进行，决定“已经切成这样的一个区间，应当用哪种结构存放”，其结果只影响该叶子内部的查找与存储，不影响上层。该决策只需感知叶子自身的键分布与容量，因为 2.2 节的代价分析表明，两种叶型在点查、范围与内存上的差异都可以在单叶范围内量化。

将两者分离的好处是责任清晰：树形不合理表现为层级过深或叶子过大过小，由 TSMDP 侧的实验评价；叶型不合理则表现为某些叶子的代价估计与实际不符，由式 (2-9) 的逐项分解直接定位。二者可以在实验中独立消融，而不会相互掩盖。

## 2.5.3 构建开销与兼容性

判定对构建过程的影响集中在第三阶段，可以从时间、空间与兼容性三方面说明。

**时间开销。** 对单个叶子，构造候选哈希叶并测量 μ_H 的期望代价为 O(n)，模拟有序叶查找最坏为 O(n log n)；由于各叶子顺序处理，整个构建的额外时间不超过 O(Σ n_l log n_l) ≤ O(N log n_max)，其中 N 为数据集规模、n_max 为最大叶子的键数。当叶子尺寸相对数据集较小时，该开销与原有批量加载同阶。若构建时间对应用敏感，可将 μ_H 的实测替换为开放寻址的期望探测数解析估计，以判定精度换取构建速度；本文的默认实现采用实测，以避免解析模型与散列乘子实际行为之间的偏差。

**空间开销。** 判定过程中每个叶子临时持有一个容量为 c 的候选哈希叶，判定完成后若选择有序叶则立即释放，因此额外空间的峰值为 O(n_max)，不随叶子数量累积，也不进入最终索引。索引的常驻内存只由被选中的叶型决定。

**与原有流程的兼容性。** 当所有判定条件关闭时，叶子构造执行与原始实现相同的路径：不复制键集合、不排序、不做额外的查找模拟，直接按原有装载因子构造哈希叶。因此判定机制可以被视为构建流程上的一个可插拔环节，其开启与关闭不会改变内部节点的构造方式，也不会改变索引对外提供的查询接口，这为后续实验中的对照提供了基础。

综上，叶型判定被放置在自顶向下划分的末端，以逐叶、终态、局部的方式接入，既保持了与原有构建流程的兼容，也把额外开销限制在叶子尺度。2.6 节将进一步分析该机制的正确性、复杂度界以及权重取值对它行为的影响。
