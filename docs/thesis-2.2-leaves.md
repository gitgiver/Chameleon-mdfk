# 2.2 有序叶与哈希叶的结构与操作

本节从物理组织与基本操作两个方面，对哈希叶与有序叶进行统一描述，为 2.3 节的代价建模建立共同的计量口径。为避免受具体数据类型影响，本文以槽（slot）作为叶内存储的基本单位：每个槽存放一个键值对，叶的容量 c 表示槽的数量，叶内实际存放的键数记为 n，装载因子定义为

α = n / c                                                      (2-1)

叶型判定所比较的各项代价，最终都折算为“每键占用的槽数”或“每次查询访问的槽数”，从而与槽的具体字节宽度无关。

## 2.2.1 哈希叶

哈希叶沿用 Chameleon 原有的叶节点组织方式，其物理布局由三部分组成：一是叶头元数据，记录该叶覆盖的键区间 [lower, upper]、容量 c、有效键数 n、最大探测半径 r 以及叶型标志；二是长度为 c 的槽数组；三是位图，每个槽对应一位，标记该槽是否已写入有效键值对。位图的存在使叶可以容忍空洞：未写入的槽虽然占据空间，却不会被误判为命中。

每个哈希叶内部维护一个基于自身键区间的线性模型。对于任意键 k，模型先给出其在 [0, c−1] 上的预测位置 f(k)，再将该预测位置乘以固定散列乘子 H 并对容量取模，得到起始桶

h(k) = ⌊ f(k) · H ⌋ mod c                                     (2-2)

乘子的作用是打散相邻键的起始桶，避免局部预测误差在相邻槽位上累积成一条长探测链。

点查从起始桶 h(k) 出发，按距离 i = 0, 1, …, r 向左、右两侧交替探测，越过边界时按容量回绕。对每个被探测的槽，先检查位图，再比较键：位图有效且键相等即命中；在最大探测半径内均未命中则判定键不存在。因此单次点查访问的槽数不超过 2r + 1，理想情况下（无冲突）为 1。最大探测半径 r 由插入过程动态维护：若新键在既有半径内找不到空槽，插入会继续向外探测并更新 r，故 r 反映了该叶的实际冲突程度。

插入沿与点查相同的路径寻找首个空槽并写入位图。当有效键数超过容量与装载因子上限的乘积时，叶触发扩容，按目标装载因子重新分配容量并重建。

范围查询暴露了哈希叶的固有弱点。由于槽按散列位置排列而非键序排列，区间 [lo, hi] 内的键可能落在任意槽上，扫描既没有可用的起点，也不能在遇到比 hi 大的键时提前终止，只能遍历全部 c 个槽并逐槽判定是否落在区间内。换言之，哈希叶的范围查询代价与容量线性相关，为 O(c)。

在内存方面，哈希叶为每键占用 1/α 个槽。当 α < 1 时，空洞构成空间放大，且该放大量由构建时设定的装载因子决定，与叶子的实际访问热度无关。

## 2.2.2 有序叶

有序叶采用稠密有序布局：容量取 n 与最小叶容量中的较大者，前 n 个槽按键升序连续存放，不存在空洞，因此装载因子恒为 1。位图仍被保留，用于与哈希叶共享同一套访问接口。

有序叶的点查同样以叶内最小键与最大键为端点建立线性模型，预测位置为

p = ⌊ (n−1) · (k − k_min) / (k_max − k_min) ⌋                (2-3)

并按 [0, n−1] 裁剪。一次预测访问后，若 p 处的键恰为目标键则直接命中；否则根据目标键位于 p 的哪一侧，先以倍增步长向外做 gallop 搜索，确定一个包含目标键的括号区间，再在该区间内二分。设预测位置与目标真实位置的偏差为 g（以槽计），则点查代价为 1 + O(log g) + O(log g)：当局部键分布接近均匀时 g 很小，查找接近 O(1)；最坏情况下退化为 O(log n)。与哈希叶的关键区别在于，预测误差在这里不表现为探测链，而表现为一个有界窗口，窗口大小可以直接测量，这为 2.4 节基于预测误差窗口的判定提供了依据。

有序叶的范围查询只需在叶内对 lo 做一次二分（lower bound）即可定位起点，随后顺序扫描，遇到首个大于 hi 的键立即终止，扫描只触碰结果本身及常数个额外槽。定位代价为 O(log n)，与叶的容量无关。

有序叶的代价是布局刚性：稠密有序意味着插入新键需要搬移其后所有槽位，删除同样会破坏连续性。本文因此将有序叶用于批量加载完成后的读多写少或只读场景，动态插入仍由哈希叶承担。这一适用边界将作为叶型判定机制的约束条件之一。

## 2.2.3 两种叶子的代价特性对比

两种叶子的代价特性汇总于表 2-1。

**表 2-1 哈希叶与有序叶的代价特性对比**

| 维度 | 哈希叶 | 有序叶 |
| --- | --- | --- |
| 物理组织 | 开放寻址 + 位图，允许空洞 | 稠密有序数组，无空洞 |
| 点查 | 预测桶 + 双向探测，O(r) | 预测 + gallop + 二分，O(log g)，最优 O(1) |
| 范围定位 | 无键序，退化为扫描全部 c 个槽，O(c) | 二分定位，O(log n) |
| 范围扫描 | 输出无序，需过滤全叶 | 输出有序，只触碰结果 |
| 每键内存 | 1/α 个槽 | 1 个槽 |
| 构建 | 逐键散列插入，期望 O(n) | 排序后顺序写入，O(n log n)（有序输入下 O(n)） |
| 动态插入 | 支持，超出装载因子上限时扩容 | 不支持，需搬移或重建 |

由表可见，两种叶子最本质的差异在范围查询：哈希叶的定位代价为 O(c)，有序叶为 O(log n)，而 c 本身随 n/α 增长，因此哈希叶的范围代价随叶尺寸线性增长，有序叶仅与叶尺寸的对数相关。这一差异正是 2.3 节将范围代价取为 ρ_h = c、ρ_o = log₂ n 的依据。

另一点值得强调的是，两种叶子的点查代价可以在同一单位下直接比较：哈希叶按实际访问的槽数计数（包含最终命中槽），有序叶按预测访问加上 gallop 与二分的每一步计数，二者都是“槽访问次数”。内存代价同理，均以“槽/键”度量，而槽的字节宽度在两种叶型中相同，可在比较中约去。正是这种统一的计量方式，使得后文的代价模型无需依赖具体数据类型即可在两种叶型之间作出判定。
