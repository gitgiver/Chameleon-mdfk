# 2.7 本章小结

本章针对第一章指出的哈希叶空间放大问题，设计了有序叶与哈希叶的逐叶决策机制。哈希叶为降低冲突而预留的空闲槽位，其大小由构建时的装载因子决定，与叶子的实际访问热度无关；在数据或查询接近均匀的区段，这部分预留空间既没有差异化的依据，也无法被回收。有序叶采用稠密有序布局，每键恰好占用一个槽，并在范围查询上具有定位代价仅与叶尺寸对数相关的优势。本章的基本思路是：让两类结构在同一个叶子上按各自的真实代价竞争，由代价较低者胜出。

围绕这一思路，本章完成了以下工作。首先，描述了两种叶子的物理组织与基本操作，并以槽为统一单位刻画了它们在点查、范围查询与内存上的代价特性。其次，建立了加权代价模型，将每键平均点查槽访问数、范围定位槽数与每键内存槽数线性组合；三项均以槽计量，因而与数据类型和槽的字节宽度无关。在此基础上，给出了双侧代价判定：对每个候选叶子分别构造并估计两种形态的代价，当有序叶相对哈希叶的代价差为负时选择有序叶。该判定不含需要人工整定的偏斜度或误差阈值，其依据完全来自叶子自身的数据与结构代价。最后，说明了判定在自顶向下构建流程中的接入位置——划分完成后、叶子定型的终态阶段，并分析了它的正确性、复杂度与权重行为：判定不改变叶内键集合与索引语义，额外开销被限制在叶子尺度，且其结果随内存权重、范围权重与预测精度单调变化。

本章的设计存在明确的适用边界。有序叶不支持原地插入，因此该机制面向批量加载后的读多写少场景；对需要频繁更新的叶子，仍应保留哈希叶或在其重建时重新判定。此外，本章只回答“一个叶子应当采用哪种结构”，并未涉及哈希叶内部应当多稀疏或多稠密。对于偏斜负载中保留下来的哈希叶，其装载因子如何随叶子热度调整、如何在运行过程中跟踪热冷迁移，将在第三章中讨论。
