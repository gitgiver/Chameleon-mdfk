# 3.1 实验设置

本章实验围绕第二章设计的叶型决策机制展开，目的是回答三个问题：判定是否按设计在局部均匀区段选择有序叶、在偏斜区段保留哈希叶；转换之后点查、范围查询与内存各发生什么变化；判定机制自身的构建代价有多大。为便于对照，本节先说明实验平台、数据集、查询负载、度量口径与实验配置，后续各节如无特别说明，均沿用本节设定。

## 3.1.1 实验环境

实验运行在双路 AMD EPYC 7402 服务器上，共 48 个物理核、96 个硬件线程，主频 2.8 GHz，内存 503 GB；策略网络的前向推理运行在 NVIDIA RTX 3090（24 GB 显存）上。操作系统为 Linux 5.15，编译器为 g++（C++17 标准，`-O3 -march=native` 优化），深度学习框架为 PyTorch 的 C++ 前端（libtorch）配合 CUDA。

索引与查询的全部计时均在同一进程内完成，计时区只包含索引操作本身：查询所需的随机数、键的下标与查询序列都在计时区之外预先产生，避免随机数生成与数据访问模式干扰测量。策略网络的参数在实验开始前一次性载入，构建阶段的每次扇出决策需要一次 GPU 前向，其开销在 3.6 节单独讨论。

## 3.1.2 数据集

实验使用真实数据与合成数据相结合的五个数据集，其分布性质与实验用途如表 3-1 所示。所有数据集在构建前按 key 升序排序，以满足批量加载对有序输入的要求；键值对类型为 `<double, double>`，每个槽占 16 字节，2000 万条记录的数据本身约 320 MB。

**表 3-1 实验数据集**

| 数据集 | 全量规模 | 实验切片 | 分布性质 | 用途 |
| --- | --- | --- | --- | --- |
| uden | 2 亿 | 2000 万 / 5000 万 | 完美均匀：键为连续整数，各十分位恰好占 10% | 均匀负载基线 |
| face | 2 亿 | 2000 万 / 5000 万 | 极端偏斜：键高度集中在键域低端 | 偏斜负载 |
| local_skew | 2000 万 | 2000 万 | 一万个簇，每簇约 2000 个键，簇内标准差 0.05 | 局部偏斜 |
| mixed | 2000 万 | 2000 万 | 前半段均匀、后半段由 5000 个紧簇构成 | 同一索引内混合分布 |
| logn | — | 5000 万 | 对数正态：密度沿键轴平滑变化，叶内间距近似恒定 | 平滑非均匀 |

需要说明的是，`uden` 与 `face` 的实验切片并非各自全量分布的代表：`uden` 取全量前 2000 万个连续整数，`face` 取全量中最小的 2000 万条记录，落于全量键域的前 4.1×10⁻¹⁰。因此本章的结论刻画的是这些切片上的行为，不能直接外推到全量数据；这一点在 3.7 节作为局限再次说明。`local_skew`、`mixed` 与 `logn` 的切片覆盖了各自的全部分布，但 `logn` 只取前 5000 万个键。

## 3.1.3 查询负载

**点查负载。** 点查的 key 从数据集内按键名次均匀抽取，查询序列由固定种子生成，从而保证同一配置可复现。每次运行完成 4000 万次点查，按 5 轮切分、每轮 800 万次；首轮作为预热丢弃，取其余 4 轮的统计量作为有效测量。每条查询在计时区内只执行一次 `Index::get()`，并在计时区外与数据集中对应的 value 逐条比对。

**范围查询负载。** 范围查询的构造需同时满足两个要求：查询代价能够反映叶型差异，结果规模又便于跨数据集比较。为此，本文采用两种互补的构造方式。

记数据集按键升序排列为 D = (d_0, d_1, …, d_{N−1})，其中 d_i 表示第 i 条记录，key(d_i) 为其关键字，N 为记录总数。查询区间取闭区间 [lo, hi]，返回所有满足 lo ≤ key(d_i) ≤ hi 的记录。两种方式均以记录的名次（即其下标 i）为随机变量，而非直接在键值轴上抽样。其原因是名次区间与键区间一一对应，可避免在键域稀疏处抽到空区间。

**名次跨度模式。** 该模式为主负载。给定选择性 s ∈ (0, 1)，定义跨度

m_s = max{1, ⌊sN⌋}.                                               (3-1)

从整数集合 {0, 1, …, N−m_s−1} 中均匀抽取起点 r，并令

lo = key(d_r),   hi = key(d_{r+m_s}).                             (3-2)

由于 D 已按键升序排列且不含重复键，区间 [lo, hi] 恰好覆盖 d_r 至 d_{r+m_s} 共 m_s+1 条记录，与局部键密度无关。因此，同一 s 在不同数据集上得到相同规模的结果集，其延迟可直接比较。实验中 s 取 10⁻⁶ 至 10⁻² 五个量级。

每档每轮的查询次数定义为

Q_s = min{ 2×10⁶, max{200, ⌊2×10⁸ / m_s⌋} }.                      (3-3)

式 (3-3) 将每轮扫描的名次总量约束在 2×10⁸ 附近：m_s 较小时增加查询次数，以保证单轮时长；m_s 较大时减少查询次数，以控制单轮时长；上下界同时保证样本量足够。由此，结果规模与扫描总量相互独立，便于在测量中分离定位代价与输出代价。

**键宽模式。** 该模式为辅助负载。给定键宽 W > 0，从 {0, 1, …, N−1} 中均匀抽取起点 r，并令

lo = key(d_r),   hi = lo + W.                                     (3-4)

结果集为键区间 [lo, lo+W] 内的全部记录，其规模由该区间的局部键密度决定。同一 W 在不同数据集上对应的结果规模不同：uden 的键近似等距，W = 10⁴ 对应约 10⁴ 条记录；face 的键高度聚集，同一 W 仅对应约 10² 条记录。因此，W 不宜跨数据集比较；键宽实验在同一数据集内比较不同 W，跨数据集分析时以平均结果规模为横轴。每档执行 20000 次查询，并记录结果规模的最小值、中位数、90 与 99 分位数、最大值以及空结果比例。

两种模式互为补充：名次跨度模式固定结果规模，用于分离叶型对定位代价的影响；键宽模式保留真实查询中随密度变化的结果规模，用于检验机制在非均匀键域上的行为。若以键域的固定比例构造区间，结果规模将随密度剧烈变化，跨数据集的延迟比较会混入输出规模的差异，故不将其作为主负载。

**正确性校验。** 以直接扫描数据集得到的答案作为基准。由于 D 已排序，区间 [lo, hi] 的期望结果为从首个关键字不小于 lo 的记录，到最后一个关键字不大于 hi 的记录之间的切片。对每次查询，先比对结果条数；再对前 200 次查询，将索引返回的记录按关键字排序后与基准切片逐元素比对。有序叶按键序返回结果，哈希叶按槽序返回结果，故比对在多重集意义下进行，不要求顺序一致。两种模式的全部运行均未出现结果错误。需要说明，实验数据不含重复键，因此同一键占多个槽位时的语义未被覆盖，这一点在 3.7 节列为局限。

**计时协议。** 两种模式的随机起点均在计时区间之外预先生成，计时区间内只包含索引的范围查询操作。每档分 5 轮执行，首轮作为预热丢弃，取其余 4 轮的最小值。选择性较大的档（s ≥ 10⁻²）输出规模可达数亿条记录，受内存带宽限制，读数波动较大；绘制曲线时截取到 s ≤ 10⁻³，或在该档明确标注带宽受限。

## 3.1.4 度量指标与测量协议

本章使用四类指标。

- **点查延迟**：单次 `get()` 的纳秒数，并可按 1/延迟 换算为百万次查询每秒（Mops/s）。
- **范围查询延迟**：单次 `range_query()` 的纳秒数，以及扣除结果条数影响后的每结果纳秒数。
- **内存占用**：`mem_ratio` 定义为索引常驻字节数除以数据集原始字节数（N × 16 B），同时报告绝对占用（MB）。该比值中 1.0 表示索引与数据等大，超过 1.0 的部分即索引自身的空间开销。
- **构建时间**：`bulk_load` 的毫秒数，包含策略网络的扇出决策与叶型判定。

测量协议如下。每种配置重新构建一次索引，点查与范围查询共享同一次构建。每一轮给出平均延迟，点估计取 4 个有效轮的最小值；最小值是对干扰的单侧估计，比平均值更稳定。所有运行的点查 `errors = 0`；范围查询对每条查询比对结果条数，并抽样前 200 条按多重集逐元素比对，同样 `errors = 0`。重复实验表明，同一配置的运行间差异约为 1%~5%，因此本章不把小于 5% 的跨条目差异解读为真实差异。范围查询中较宽的选择性档（s ≥ 10⁻²）受内存带宽限制，读数波动更大；引用曲线时截取到 s ≤ 10⁻³，或在该档明确标注带宽受限。

## 3.1.5 实验配置与对照

实验包含结构配置与叶型配置两类。

**结构配置。** 全部实验采用 `structure=policy`：树形与每个内部节点的扇出由 DARE 与 TS-MDP 两个智能体决定，与原始 Chameleon 的构建方式一致。本文不人为固定树形，因为叶型判定是作为构建流程的一部分投入实际索引的，实验要回答的正是这种真实集成形态下的表现；各对照共享同一套结构决策流程，因此读数差异仍可归因于叶型配置。

**叶型配置。** 主实验采用第二章的双侧代价判定（`LEAF_COST_DECISION=1`）：对每个叶子分别估计有序叶与哈希叶的点查、范围与内存代价，取代价较低者。权重中 `w_q` 与 `w_m` 沿用多智能体奖励的查询与内存权重，`w_r` 通过独立参数配置：点查导向实验取 `w_r = 0`，范围导向实验取 `w_r > 0`。为给出有序叶的收益与代价上界，另设权重极值配置：只保留内存项（`w_m > 0`，`w_q = w_r = 0`）或只保留范围项（`w_r > 0`，`w_q = w_m = 0`），此时全部合格叶都会转为有序叶。该配置由同一代价模型在极端权重下产生，不引入额外判据。

**测量路径。** 本章主表全部来自生产路径：`benchmark/prod_bench.cpp` 编译时不开启 `PILOT_DIAGNOSTICS`，查询走普通 `get()` 与 `range_query()`，查询路径不写任何共享诊断状态。带逐叶诊断的插桩构建只用于机制分析，其结果不与主表混用。

上述配置的汇总如表 3-2 所示。
