# 2.3 决策问题建模

2.2 节表明，两种叶型在点查、范围查询与内存三个维度上各有代价，叶型判定的实质是在每个叶子上对这三种代价做权衡。本节将这一权衡形式化为一个可计算的优化问题，并说明其可分解性以及各项代价的计量口径。

## 2.3.1 决策变量与目标

设索引共包含 L 个叶子，第 l 个叶子存放 n_l 个键，其叶型用二值变量 x_l ∈ {O, H} 表示，其中 O 表示有序叶，H 表示哈希叶。叶型判定的目标是使整个索引的总查询代价最小。

记一次查询在第 l 个叶子上产生的代价为 C_l(x_l)，单位时间内该叶承担的查询次数为 Q_l，则索引的总代价为

T = Σ_l Q_l · C_l(x_l)                                         (2-4)

在判定阶段，本文假设同一叶子内各键被等概率访问，即每个键的平均访问速率为常数 q̄，于是 Q_l = n_l · q̄。代入式 (2-4) 得

T = q̄ · Σ_l n_l · C_l(x_l)                                     (2-5)

由于 q̄ 与叶型无关，最小化 T 等价于逐叶最小化 C_l(x_l)。这一分解成立的原因在于：叶与叶之间不共享存储，一次查询的路由路径只经过其所在的叶子，某个叶子的叶型选择既不影响其他叶子的代价，也不改变树形与路由结构。因此，原问题可分解为 L 个相互独立的二选一子问题：

x_l* = argmin_{x ∈ {O, H}} C_l(x),  l = 1, 2, …, L            (2-6)

这一可分解性是 2.4 节采用逐叶判定、并在构建阶段一次性完成判定的前提。

需要说明的是，等概率假设只服务于叶型判定，并不意味着本文忽略访问热度。热度对空间分配的影响将在第三章通过逐叶装载因子单独处理；本章的判定只回答“在该叶的数据分布与结构特征下，哪种叶型更合适”。将两者分开，也使本章的结论不依赖于具体负载，而第三章的优化可以在叶型确定之后独立进行。

## 2.3.2 代价模型

将三种代价按权重线性组合，第 l 个叶子在叶型 x 下的代价定义为

C_l(x) = w_q · μ_l(x) + w_r · ρ_l(x) + w_m · m_l(x)            (2-7)

其中，μ_l(x) 为每键平均点查槽访问数，ρ_l(x) 为范围查询的定位槽数，m_l(x) 为每键占用的内存槽数；w_q、w_r、w_m 为对应的非负权重。

式 (2-7) 的基本思想是统一计量单位。μ 与 ρ 描述一次查询访问的槽数，m 描述一个键占用的槽数，三项都以槽为单位，因而与槽的具体字节宽度无关。这一归一化带来两点好处：其一，同一组权重可以直接用于不同数据类型、不同叶容量下的判定；其二，权重只具有相对意义，将三者同时缩放不改变判定结果，从而避免了为物理单位赋值的问题。

权重的取值与系统保持一致：w_q 与 w_m 沿用多智能体奖励中的查询代价权重与内存代价权重，使叶型判定与树形决策遵循同一套取舍标准；w_r 则作为独立的可配置参数，默认取 0，此时模型退化为点查与内存的二维权衡，适用于以点查为主的负载；当负载包含范围查询时，令 w_r > 0，范围定位代价即被纳入判定。

## 2.3.3 各项代价的取值与口径

式 (2-7) 中三项代价在两种叶型下的取值汇总于表 2-2。

**表 2-2 代价模型中各项的取值**

| 符号 | 含义 | 哈希叶 | 有序叶 |
| --- | --- | --- | --- |
| μ | 每键平均点查槽访问数 | 构建时实测，单次不超过 2r + 1 | 1 + O(log g)，可按查找路径模拟求均值 |
| ρ | 范围查询定位槽数 | c | ⌈log₂(n + 1)⌉ |
| m | 每键内存槽数 | c / n = 1 / α | 1 |
| 构建代价 | 一次性开销 | 期望 O(n) | O(n log n)，有序输入下 O(n) |

各项的具体口径如下。

**点查代价 μ。** 哈希叶的 μ_H 在构建阶段直接测量：对叶内每个键执行一次点查，累计实际访问的槽数并取平均，计数包含最终命中的槽，因此与有序叶的计数口径一致。单次点查的槽访问数上界为 2r + 1，该值随叶内冲突程度变化，无法仅由 n 与 c 推出，故采用实测而非解析估计。有序叶的 μ_O 由“一次预测访问 + gallop 步数 + 二分步数”构成，可按 2.2.2 节的查找路径对每个键模拟并求平均；解析上它等于 1 + O(log g)，其中 g 为预测位置与真实位置之间的偏差窗口。

**范围代价 ρ。** ρ 只计定位代价。哈希叶没有键序，必须以全容量扫描作为定位手段，故 ρ_H = c；有序叶通过一次二分定位起点，故 ρ_O = ⌈log₂(n + 1)⌉。两种叶型在定位之后的结果输出代价相同，因此在比较中相互抵消，不需要显式建模。

**内存代价 m。** 内存以每键占用的槽数度量。哈希叶的容量为 c，对应 m_H = c / n = 1 / α；有序叶为稠密布局，对应 m_O = 1。由于判定中只允许容量足够大的叶子转为有序叶，m_O = 1 的前提总是成立。

**构建代价。** 构建代价属于一次性开销，不参与式 (2-7) 的每次查询比较，但其影响需要在机制层面加以控制：哈希叶的构造与测量可在一次遍历内完成，有序叶需要预先获得有序键序列。本文在 2.5 节讨论如何将其控制在与原有构建过程相同的数量级内。

## 2.3.4 建模假设

上述模型建立在以下三条假设之上，后续的判定机制与实验分析均以之为前提。

第一，判定阶段叶内各键等概率访问。该假设使式 (2-5) 成立，是逐叶分解的依据；访问热度的影响由第三章的装载因子机制承担。

第二，代价只计定位过程，结果输出代价在两种叶型间相同。这一假设在点查下自然成立，在范围查询下要求两种叶型返回相同的结果集合，而这一性质由索引的语义保证。

第三，槽的字节宽度在两种叶型间一致。因此以槽为单位的代价可以直接比较，且 m 中无须出现具体字节数。

至此，叶型判定已被转化为对式 (2-7) 的逐叶比较问题。2.4 节在此基础上讨论具体的判定准则及其实现方式。
