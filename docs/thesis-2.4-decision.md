# 2.4 基于双侧代价的判定机制

2.3 节将叶型判定归结为式 (2-7) 的逐叶比较。本节给出该比较的具体形式、执行过程与边界条件。所谓“双侧”，是指判定并不依赖数据分布的单侧特征（如偏斜度或预测误差）去猜测哪种叶型更合适，而是对候选叶子的两种形态分别估计代价，再在两侧之间取小。因此判定不需要人工整定的结构阈值，其结果完全由叶子自身的数据与两种结构的实际代价决定。

## 2.4.1 判定准则

对第 l 个叶子，分别以有序叶与哈希叶计算式 (2-7)，得到 C_l(O) 与 C_l(H)。判定规则为

x_l = O，当且仅当 n_l > N_min 且 C_l(O) < C_l(H)；否则 x_l = H        (2-8)

其中 N_min 为允许转为有序叶的最小叶容量，其作用见 2.4.3。判定采用严格小于而非小于等于，使两种叶型代价相同时保守地保留哈希叶，避免在无收益时改变原有布局。

将式 (2-7) 展开，定义有序叶相对哈希叶的代价差

Δ_l = C_l(O) − C_l(H)
    = w_q · (μ_O − μ_H) + w_r · (ρ_O − ρ_H) + w_m · (m_O − m_H)      (2-9)

则判定规则等价于：当 Δ_l < 0 时选择有序叶。式 (2-9) 将两侧的差异分解为三项，每一项的符号都有明确的物理含义。

**点查项 w_q · (μ_O − μ_H)。** 该项的符号取决于叶子内部预测的准确程度。当键在叶内接近均匀分布时，有序叶的预测位置接近真实位置，gallop 与二分的步数很少，μ_O 接近 1，该项接近于零甚至为负；当局部分布偏斜、预测偏差窗口 g 变大时，μ_O 随 log g 增长，该项转为正，构成对有序叶的惩罚。因此这一项刻画的是“有序叶为换取其他收益而在点查上付出的潜在代价”。

**内存项 w_m · (m_O − m_H)。** 由表 2-2，m_O = 1、m_H = c/n = 1/α，故该项等于 w_m · (1 − c/n)。只要装载因子 α < 1，该项即为负，表示有序叶的固定内存收益；且 α 越低，收益越大。该项与查询分布无关，是有序叶最稳定的优势来源。

**范围项 w_r · (ρ_O − ρ_H)。** 由表 2-2，ρ_O 为 O(log n)、ρ_H 为 c，故该项在 n > 1 时恒为负，表示有序叶在范围定位上的固有优势；范围查询在负载中的权重越大（w_r 越大），这一项对判定的影响越强。当 w_r = 0 时，该项被移除，判定退化为点查与内存的二维权衡。

综上，式 (2-9) 的判定本质是在“内存收益 + 范围收益”与“点查代价”之间求差：前两项之和为负、且其绝对值大于点查项时，有序叶胜出；否则保留哈希叶。这一形式既不需要为偏斜度或误差窗口设定阈值，也使判定结果可以逐项回溯——当某个叶子的选择与直觉不符时，可以直接由式 (2-9) 指出是哪一项主导了结果。

## 2.4.2 判定过程

式 (2-9) 所需的六项代价中，ρ 与 m 可直接由 n、c、α 算出，关键是如何在构建阶段得到 μ_H 与 μ_O。此处不采用解析估计，原因是哈希叶的实际查找代价依赖预测位置、散列乘子与插入顺序共同形成的冲突结构，无法仅由 n 与 c 准确刻画；而有序叶的 μ_O 又必须与 μ_H 在同一口径下计数，否则比较会系统性偏移。本文因此对两种形态分别做一次实际测量。

具体过程如下。首先按目标装载因子 α 计算候选容量 c = max(⌈n/α⌉, N_min)，并在该容量上构建一个哈希叶，将叶子内的全部键插入其中。随后对叶子内每个键在该哈希叶上执行一次点查，累计访问的槽数并取平均，得到 μ_H。计数包含最终命中的那个槽：若省略命中槽，无冲突的哈希叶会被计为“零访问”，从而在比较中不公正地占优。μ_O 则按 2.2.2 节有序叶的实际查找路径，对叶子内每个键模拟一次“预测访问 + gallop + 二分”，以同样的方式累计槽数并取平均。两侧的计数单位因此严格一致，都是“一次点查访问的槽数”。

完整的判定过程如算法 2-1 所示。

**算法 2-1 基于双侧代价的逐叶判定**

输入：叶子内的键集合 K，规模 n，键区间 [lower, upper]，权重 w_q、w_r、w_m，目标装载因子 α
输出：该叶子的叶型及其存储结构

1. c ← max(⌈n / α⌉, N_min)
2. 在容量 c 上构建哈希叶 H，插入 K 中的全部键
3. 对 K 中每个键在 H 上执行一次点查，累计访问槽数 S_H
4. μ_H ← S_H / n；μ_O ← 按有序叶查找路径对 K 中每个键模拟并累计，取平均
5. ρ_H ← c；ρ_O ← ⌈log₂(n + 1)⌉；m_H ← c / n；m_O ← max(n, N_min) / n
6. C_H ← w_q·μ_H + w_r·ρ_H + w_m·m_H；C_O ← w_q·μ_O + w_r·ρ_O + w_m·m_O
7. 若 n > N_min 且 C_O < C_H：
8.     释放 H，构建稠密有序叶并返回
9. 否则：
10.    保留 H 作为该叶的最终结构并返回

算法在构建阶段对每个叶子执行一次，其时间复杂度为：构建与测量哈希叶期望 O(n)，模拟有序叶查找最坏 O(n log n)，合计与原有批量加载同阶；额外空间为临时哈希叶，规模为 O(n)。判定完成后，未被选中的结构立即释放，不进入最终索引。

## 2.4.3 边界条件与保护规则

为保证判定在各类叶子上的行为可预期，机制设置了以下约束。

**最小叶容量 N_min。** 当叶子过小时，有序叶的固定开销（一次预测访问、gallop 的起步步骤）相对于哈希叶的少量探测不再具有优势，且为其单独维护有序布局并不划算。因此规定只有 n > N_min 的叶子才允许转为有序叶；不满足该条件时无论式 (2-9) 的结果如何，一律保留哈希叶。这一约束同时保证了 m_O = 1 的取值前提。

**代价相同时保留哈希叶。** 式 (2-8) 采用严格小于，等价于在 Δ_l = 0 时选择哈希叶。哈希叶是系统原有的结构，这一偏向使判定在没有明确收益时不会改变原有行为，也使关闭判定机制后的路径与原始实现逐字节一致，便于实验对照。

**候选结构的复用。** 若判定结果为哈希叶，算法直接保留测量阶段已构建的候选叶，不再重建；只有判定为有序叶时才释放候选叶并构建稠密布局。因此测量过程不引入额外的重复构建开销。

**对上层透明。** 两种叶型共享同一套叶节点接口，点查与范围查询在叶内依据叶型标志分派，内部节点的路由、树形以及并发读路径均不感知叶型差异。因此叶型判定是一个纯局部的构建期决策，不影响 2.3 节所依赖的可分解性。

**写负载的适用边界。** 如 2.2.2 节所述，有序叶不支持原地插入。因此本机制面向批量加载后的读多写少场景；若某叶子后续需要承载频繁插入，应由上层在触发该叶重建时重新判定，或直接回退为哈希叶。该边界是判定机制的适用条件，而非其内部逻辑的一部分。

至此，叶型判定已由式 (2-9) 完全确定：输入是叶子自身的键集合与容量，输出是两种叶型中代价较低者。2.5 节讨论如何将该判定嵌入索引的整体构建流程。
