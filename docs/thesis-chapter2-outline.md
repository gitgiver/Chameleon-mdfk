## 0. 本章定位

- 承接第一章 1.3 的问题（2）：哈希叶存在与负载无关的结构性空间放大；均匀区段用有序稠密叶可同时省空间、降延迟。

- 写作原则：代价模型是正式设计；θ 偏斜阈值与窗口 p99 阈值是它的简化近似与消融对照，**不要写成三个并列方案**。

### 2.2 两种叶子的结构与操作

**要写的内容**

- 2.2.1 哈希叶
  - 开放寻址 + 位图标记有效槽（bitmap）。
  - 点查：线性模型预测桶 → 以预测槽为中心左右交替探测，`max_offset` 限界。
  - 容量由装载因子决定，存在空洞。
- 2.2.2 有序叶
  - 稠密键序数组（密度 1.0），无空洞。
  - 点查：预测位置 → gallop 定位 → 二分。
  - 天然支持范围查询与顺序扫描。
- 2.2.3 两种叶子的代价特性对比
  - 表 2-1：点查 / 范围查定位 / 内存 / 构建开销 四行。
  - 题眼：哈希叶做范围定位必须扫全容量（`range_h = capacity`），有序叶只需 `log2(n)`。

**写作要点**

### 2.3 决策问题建模

**要写的内容**

- 2.3.1 决策变量与目标
  - 每叶二值 `x_l ∈ {ordered, hash}`，目标为全索引加权总代价最小。
  - 论证可分解性：叶间不共享存储、查询路径只经过所在叶，故可逐叶独立决策。
- 2.3.2 代价模型

  ```
  C = w_q · μ + w_r · ρ + w_m · m
  ```

  - μ：每键平均点查访问槽数。
  - ρ：范围查询定位槽数。
  - m：内存槽数比（capacity / size）。
- 2.3.3 各项取值与口径
  - μ_h：构建时实测（逐键计数，包含命中槽）。
  - μ_o：解析计算（预测一次 + gallop + 二分，见 `mean_ordered_steps`）。
  - m_o = 1，m_h = capacity / n。
  - ρ_o = log2(n)，ρ_h = capacity。
  - **假设声明**：只计定位代价，结果输出代价两种叶型相同，在比较中抵消。

**写作要点**

- 重点强调归一化技巧：三项都换算为"槽"，与槽的字节大小无关，使同一组权重跨数据集可比。这是本章可迁移性的来源。
- 公式必须编号。

## 3. 术语约定

- **装载因子 / 密度**：统一为 `density = size / capacity`，正文只用一个词（建议"装载因子"），代码中的 `density` 在首次出现时注明。
- **槽（slot）**：叶子数组的一个元素位置，代价计量的统一单位。
- **预测误差窗口（window）**：点查时需要搜索的槽数，p99 为分位数。
- **探测槽数（probe）**：一次点查实际访问的槽数，含命中槽。
- **局部偏斜（skew）**：叶所在键区间内的分布偏斜度；仅用于实验章消融对照，正文 2.4 采用双侧代价判定。
